Section 508 document checklist: Word, PowerPoint, PDF

By Preflight A11y · 29 October 2026 · 7 minute read

This is a practical checklist for teams that need to hand over accessible Word, PowerPoint, or PDF files. It separates what an automated preflight can check from what a person must verify.

Scope note: Section 508 applies to U.S. federal agencies and the ICT they procure, develop, maintain, or use. Universities, contractors, and private organisations may also be covered by Section 504, the ADA, procurement terms, or state law. This checklist is not legal advice.

1. Word (DOCX) checklist

ItemWhat to verifyHow
Document titleA descriptive title in File → Info → PropertiesCheck manually; a preflight can flag a missing title.
LanguageDefault language set; foreign phrases markedReview → Language.
HeadingsReal Heading 1/2/3 styles, in orderNavigation pane; do not use bold text as a heading.
ImagesPurpose-based alt text; decorative images markedRight-click → Edit Alt Text.
TablesHeader row; repeated header row; simple gridTable Layout → Repeat Header Rows.
LinksDescriptive text, not “click here”Review every link in context.
Text boxesReading order is sensibleScreen-reader test; move content into the main flow if needed.
Tracked changes/commentsAccepted/resolved before publishingReview → Track Changes / Comments.

2. PowerPoint (PPTX) checklist

  • Every slide has a unique title in the Title placeholder.
  • Reading order in the Selection Pane matches the intended order.
  • Pictures, charts, and groups have purpose-based alt text.
  • Tables have Header Row enabled.
  • No hidden slides in the published deck.
  • Embedded audio/video has captions and a transcript.
  • Body text is at least 12 pt; contrast meets WCAG AA.

3. PDF checklist

A DOCX/PPTX preflight does not make the exported PDF accessible. If the PDF is the deliverable, check separately:

  • Tagged PDF, with a logical reading order.
  • Alt text for figures and charts.
  • Bookmarks/outline for long documents.
  • Table headers and scope.
  • Form field labels and tab order.
  • OCR for scanned pages; no image-only text.
  • Document title and language in the PDF properties.

4. What automation can and cannot do

Can detectCannot verify
Missing title/language, heading structure, missing alt text, table header setting, ambiguous link text, text boxes, hidden slides, tiny text, comments/tracked changes, media presenceWhether alt text is meaningful; reading order in a real screen reader; contrast on complex backgrounds; caption accuracy; pedagogical clarity; PDF tags/reading order

5. Evidence to keep

  • Preflight report with date and tool version.
  • Manual test notes: screen reader, browser/OS, representative files.
  • Remediation log: file, change, owner, date.
  • Known limitations and exceptions.

Do not label a file “508 compliant” based on a scanner. A defensible statement is narrower: “Preflighted on [date] against the listed checks; manual review completed; known limitations documented.”
