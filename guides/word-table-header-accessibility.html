Word table header row accessibility: repeat headers and avoid merged cells

By Preflight A11y · 29 October 2026 · 5 minute read

A data table is not accessible just because it has a header row in bold. Screen readers need the header cells to be marked as headers, and they need the table structure to be simple enough to associate each value with the correct column or row.

This guide covers the practical Word fixes, what to check after them, and what a DOCX preflight can detect.

Two separate issues: “header row” tells Word/AT which cells are headers; “repeat header row” keeps that header visible when the table breaks across pages. Do both for long tables.

1. Use a real table, not tabs or a text grid

Tabs, spaces, and text boxes may look like a table but have no header/data relationships. Insert → Table, then keep the structure simple. If the content is only for layout, use a layout technique that is not a data table.

2. Mark the header row

  1. Click inside the first row.
  2. Go to Table Design (or Table Tools → Design).
  3. Enable Header Row.
  4. Keep the header text short and specific (“Enrollment”, “Deadline”, “Owner”).

3. Repeat the header row across pages

  1. Select the header row.
  2. Go to Table Layout → Repeat Header Rows.
  3. Check a page break in Print Layout: the header should repeat.

This is a visual and structural aid; it does not replace the header-row marking.

4. Avoid merged and split cells where possible

Merged cells make it harder for assistive technology to know which header applies to which value. If you must merge, keep it out of the header row and test with a screen reader. Split cells can also create ambiguous row/column relationships.

5. Add a table caption or context sentence

A short sentence before the table (“Table 2: Fall 2026 enrollment by program”) helps all readers. For complex tables, explain the structure in the surrounding text.

6. Test beyond the checker

  • Put the cursor in the table and use the screen reader’s table navigation commands.
  • Confirm the header is announced for each data cell.
  • Confirm the header repeats on a new page.
  • Check that merged cells do not make the table ambiguous.

What a DOCX preflight can detect

A browser-based preflight can flag a data table whose first row is not marked as a header, and can list the table size. It cannot know whether the header text is meaningful, whether merged cells are necessary, or whether the screen-reader experience is correct. Those are manual checks.
