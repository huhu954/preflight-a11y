DOCX alt text checker: find missing or generic image descriptions

By Preflight A11y · 29 October 2026 · 5 minute read

Alt text is one of the most common document accessibility failures, and one of the easiest to fake. An image can have “alt text” and still be useless if the description is “image1.png” or “chart”.

This guide explains what to check in a Word document and what a browser-based DOCX preflight can detect.

Purpose, not pixels. Describe what the image communicates in this document. A decorative divider should be marked decorative, not described. A chart should convey the takeaway.

Where alt text lives in DOCX

Right-click an image → Edit Alt Text. Word stores the description in the drawing properties. The Accessibility Checker can flag images without alt text, but it cannot judge whether the description is meaningful.

What good alt text looks like

Image typeWeakBetter
Photo of a classroom“image”“Students working in pairs at a science lab bench.”
Bar chart“chart”“Completion rose from 62% in week 1 to 84% in week 6.”
Decorative divider“orange line”Mark as decorative.
Logo linked to home“logo”“Example University home” (if the link purpose is not already clear).

Five checks after adding alt text

  1. No image has an empty description unless it is truly decorative.
  2. No description is just a file name, “image”, “picture”, “logo”, or “chart”.
  3. Descriptions are specific to the document’s context, not copied across every image.
  4. Charts include the takeaway, not only the chart type.
  5. Complex diagrams have a short alt text plus a longer explanation nearby.

What a DOCX preflight can detect

A browser preflight can count images, flag missing descriptions, and flag generic/filename-like descriptions. It cannot see the image, so it cannot know whether the description is accurate. It also cannot verify whether a decorative image was correctly marked as decorative.

Why browser-only matters

Course documents may contain unpublished content or student information. A browser-only checker parses the file locally; there is no upload endpoint. That reduces the data-processing surface, but it does not remove the need to use approved, non-confidential files for testing.
