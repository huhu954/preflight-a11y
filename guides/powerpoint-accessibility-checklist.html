PowerPoint accessibility checklist for course slides

By Preflight A11y · 29 October 2026 · 8 minute read

Slide decks are where accessibility work often gets skipped. A deck looks fine in presentation mode, but a screen-reader user may hear objects in the wrong order, miss the chart’s message, or land on a slide with no title.

This checklist is for course teams, instructional designers, and accessibility consultants doing a first pass. It follows the same order as a practical review: structure first, then non-text content, then interaction and media.

Important: a clean automated report does not prove WCAG conformance. Automated tools find some barriers; they cannot judge whether alt text is meaningful or whether the reading order makes sense to a person.

1. Give every slide a unique title in the Title placeholder

Use the layout’s Title placeholder, not a plain text box. Screen-reader users navigate slides by title. Duplicate titles (“Overview”, “Overview”, “Overview”) make it hard to know where you are.

If a slide is a full-bleed image, add a title that describes the slide’s message, then make the image decorative or give it alt text as appropriate. The WCAG reference is 2.4.2 Page Titled.

2. Put content in a logical reading order

Screen readers follow the object order in the file, not necessarily the visual top-to-bottom order. Open Home → Arrange → Selection Pane. Reorder objects so they read top-to-bottom, left-to-right. Decorative objects can be hidden from the reading order where the tool allows it. Then test with a screen reader.

This matters most for multi-column slides, floating callouts, and diagrams built from many text boxes. The reference is 1.3.2 Meaningful Sequence.

3. Write alt text for pictures, charts, and grouped objects

Select the object → Alt Text. Describe the takeaway, not the pixels:

  • Weak: “chart” or “screenshot”.
  • Better: “Bar chart: completed assignments rose from 62% in week 1 to 84% in week 6.”
  • Decorative: mark it decorative; do not make the screen reader announce a decorative flourish.

Grouped objects need a group-level description or meaningful child descriptions. A group with no alt text can hide the whole diagram. See 1.1.1 Non-text Content.

4. Turn on table headers

Select the table → Table Design → Header Row. Keep the header text short. Avoid merged cells where possible; a simple grid is easier for assistive technology to navigate.

If the table is only being used for layout, replace it with separate text boxes or a layout that is not a data table. The reference is 1.3.1 Info and Relationships.

5. Remove or account for hidden slides

Hidden slides can still be exported, printed, or read by some tools. If a slide is not part of the published deck, delete it. If it must stay, confirm that the export and the LMS player exclude it.

6. Caption embedded audio and video

If the deck contains video or audio, add captions and a transcript. Auto-captions can be a starting point, but they are not sufficient for technical content, names, or accented speech without review. The reference is 1.2.2 Captions (Prerecorded).

7. Check tiny text and low-contrast text

Small text is hard to read and may not resize cleanly. Use at least 12 pt for slide body text; 9 pt only for source notes. Check contrast with a contrast analyzer, especially for orange-on-cream or gray-on-white themes. The reference is 1.4.3 Contrast (Minimum).

8. Do not assume “Export to PDF” fixes accessibility

PDF has its own accessibility requirements: tags, reading order, alt text, bookmarks, and form labels. Exporting a slide deck to PDF does not automatically produce a tagged, accessible PDF. If the PDF is the deliverable, test it separately with a PDF accessibility checker and a screen reader.

CheckPass condition
Slide titleEvery slide has a unique, descriptive title in the Title placeholder.

Alt textEvery meaningful picture/chart has a purpose-based description; decorative objects are marked.
