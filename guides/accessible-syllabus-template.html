Accessible syllabus

Accessible syllabus template: structure, language, and links

By Preflight A11y · 29 October 2026 · 6 minute read

A syllabus is often the first document a student receives, and one of the most frequently updated. If it is built from an inaccessible template, every term repeats the same barriers. This guide gives a practical structure you can reuse in Word and check before publishing.

Template beats one-off fixes. Fix the heading styles, table header, link style, and alt-text workflow in the template, then every syllabus built from it starts closer to accessible.

A reusable syllabus structure

  1. Course title — Heading 1, plus term and section.
  2. Instructor and contact — Heading 2; include response-time expectations.
  3. Course description — Heading 2; plain language.
  4. Learning outcomes — Heading 2; use a real list.
  5. Schedule — Heading 2; a simple table with a header row.
  6. Assignments and grading — Heading 2; link to rubrics with descriptive text.
  7. Accessibility and accommodations — Heading 2; state how to request accommodations and where to find accessible formats.
  8. Course materials — Heading 2; identify format (DOCX/PDF/HTML) and accessibility notes.
  9. Policies — Heading 2; keep language direct.

1. Use heading styles, not bold text

Apply Heading 1 to the course title and Heading 2 to sections. A screen-reader user can jump by heading; a bold paragraph is not a heading. Keep levels in order and do not use Heading 3 just to make text smaller.

2. Set the document language

Set the default language for the document. If the syllabus includes a Spanish quotation or a French reading title, mark that phrase with the correct language. See 3.1.1 Language of Page.

3. Write descriptive links

Use the destination or action:

  • Weak: “click here”, “read more”, “link”.
  • Better: “Download the lab safety checklist (PDF)”, “Open the grading rubric”.

If the same destination appears several times, distinguish the links by context. See 2.4.4 Link Purpose.

4. Make the schedule table accessible

  • Use a real table, not tabs.
  • Turn on Header Row.
  • Repeat the header row if the table spans pages.
  • Avoid merged cells in the header.
  • Keep dates in a consistent format.

5. Use alt text only where it adds information

A decorative divider should be marked decorative. A logo linked to the university home page may need alt text that names the destination. A chart or screenshot of a schedule should convey the takeaway, not just “image”.

6. State accessibility up front

Include a short section that tells students:

  • how to request an accommodation;
  • who to contact if a material is inaccessible;
  • what formats are available;
  • how quickly the team will respond.

This is not a substitute for making the documents accessible; it is a route for problems the template cannot solve.

7. Preflight before publishing

Before the syllabus goes live, check title, language, heading order, alt text, table header, links, tracked changes, and comments. A browser preflight can catch the detectable issues; a person should still review meaning and reading order.
